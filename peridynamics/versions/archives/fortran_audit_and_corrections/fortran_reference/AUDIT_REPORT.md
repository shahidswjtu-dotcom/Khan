# Why the complete Fortran run failed

The approximately 1,300 m steel displacement has a demonstrated cause: an
incorrect force-component assignment in the supplied steel yield branch.
The full run completes numerically, but its late response is physically invalid.
The original source and completed numerical histories are retained; corrections
are explicit variants generated by `run_reference.py`, not edits to that source.

## Direct causal evidence

Original lines 746–747 copy the axial accumulator into the right endpoint's
transverse accumulators. An isolated yielded rod receives these physical forces:

| Endpoint | Original force (N) | Component-corrected force (N) |
| --- | --- | --- |
| Left | (220754.56, 0, 0) | (220754.56, 0, 0) |
| Right | (−220754.56, −220754.56, −220754.56) | (−220754.56, 0, 0) |

Thus an internal rod produces a net force instead of equal opposite forces.
For all 360 yielded elements, replaying the source loop gives −79.4716416 MN
in **each** transverse direction. With the declared steel nodal volume and
damping, the resulting terminal speed is

`(220754.56 / 1.008254e−5) / 3e6 = 7298.245614035088 m/s`.

Every component of all 362 final steel velocities matches the force-loop replay
within 3.96e−10 m/s. The giant displacement is sustained erroneous forcing
under damping; describing it solely as a timestep instability misses the cause.
Reducing the timestep cannot remove this erroneous force.

| Recorded step | Steel maximum motion | Concrete maximum motion |
| --- | --- | --- |
| 64000 | 7.637 mm | 10.418 mm |
| 65000 | 1.152 m | 0.536 m |
| 66000 | 20.533 m | 1.453 m |
| 100000 | 1300.168 m | 1.494 m |

The 1059.81 kN reaction peak is at step 64881, within this failure transition.
The original probe's 10.603 mm maximum does not show the severe motion elsewhere.
Neither number is a validated model prediction. Snapshots bracket the observed
transition; they do not record the exact first execution of the yield branch.
New runs record that first event explicitly.

## Equation-to-code audit and correction choices

| Topic | Source operation | Finding and action |
| --- | --- | --- |
| Steel axial force | 710–750, reference-direction stiffness and tensile plateau | Verified component-index error corrected by `steel_components`; pre-yield/compression and axial plateau retained |
| Physical interface force | 779–818, steel density q and concrete density −Nq | Declared volumes differ; physical resultant q(Vs−Vc) is nonzero. `interface_balance` scales only concrete return density by Vs/Vc=1.469972299; steel constitutive density is retained |
| Force/mass units | 896–926, density acceleration q/ρ | Correct active unit convention. Do not divide the same density by nodal mass. Physical rod mass is ρs vol1; concrete mass is ρc vol |
| Supports | 931–954, selected u components set zero | Corresponding v components remain nonzero, contradicting a stationary constraint. `support_velocity` resets only those v components at the original support locations |
| Contact reaction | 998–1000 and 1042–1044 | Uses concrete mass even for steel nodes. `contact_mass` uses the contacted node's density and declared volume |
| Cylinder tangential motion | 992–997 and 1036–1041 | Source resets y displacement and velocity even though contact normal is in x–z. `contact_tangent` preserves y under an explicitly declared **frictionless cylinder** interpretation; an intentional lateral restraint would be a different boundary model |
| Directional surface correction | 629–654 | `atan(abs(dy)/abs(dx))` divides by zero on some axis-aligned bonds. Explicit `--portable-angles` uses atan2; native early-run equivalence was already checked |
| Concrete force and damage | 617–680 | Constant micromodulus, tensile bilinear law, partial-volume and surface factors. Previous failure flags do not gate force. This source history choice is retained, not silently replaced with irreversible fracture |
| Steel geometric/constitutive consistency | 713–750 | Nonlinear length-based branch selection but linear reference-x elastic force and fixed-x plateau. Finite rotations give spurious forces; replacing with a corotational/plastic model requires a declared constitutive change and is not included here |
| Reaction output | 686–697 | Extra top layers are commented out, so the top-layer reaction range is empty and its load columns are zero. Use `forceld` contact reaction |
| Deflection observation | 699–703 | Original probe is (0.0095,0,−0.0095) m; sampled before update, while reaction is sampled after contact. It is not a source-verified Chapter 3 bottom-midspan sensor |
| Snapshot norm | 956–958 | Scalar displacement norm is calculated before contact and can be stale. Audit norms are recomputed from vector components |
| Time integration | 896–926 | Velocity-first Euler with explicit damping. Damping-only recurrence and isolated axial-chain bound pass at 3 µs; full damaged/contact convergence is not established |
| Initialization | Entire program | Self-contained geometry/material initialization; no external input reads. No proven undefined value explains the failure. Original author compiler settings are unknown |

The five correction options are independent. The interface normalization is
conditional on the source's declared steel volume `vol1`: it is a conservation
correction for that interpretation, not a recovered original Chapter 3 interface
calibration. No modulus, density, strength, threshold, damping, timestep, grid,
rod diameter, load amplitude or loading duration is fitted or changed.

## Verification and execution

Native compiled tests extract the actual Fortran force blocks, rather than
testing a Python rewrite. They exercise the yielded branch, existing shared-node
accumulators, pre-yield/compression, and physical interface force and virtual-work
balance, stationary support velocity, contact mass, and cylinder tangential
motion. **Seven compiled tests passed.** The original isolated yielded rod fails action–reaction; the corrected
branch passes. The corrected interface resultant is zero within 3.64e−12 N in
the synthetic nonzero-force test.

The assembled 200-step corrected run completed with bounds and floating-point
checks. Its maximum recorded physical interface resultant component was about
6.09e−16 N. This is an early elastic integration check, not validation of the
late yielded response. The earlier successful 200-step literal tests did not
exercise the defective yield branch; the new native tests close that gap.

Two **100000-step reruns are now active**:

1. `runs/steel_components_100000`: only the two component indices are corrected;
   diagnostic logging is added. This isolates the proven runaway mechanism.
2. `runs/corrected_100000`: all five options plus portable angle evaluation;
   original material inputs and full loading schedule are retained.

Both record maximum steel/concrete motion and speed, physical internal/interface
force sums, yielded rod count, and first-yield event. Their manifests identify
every correction and generated-source hash. Automatic processors create final
histories, summaries, figures and archives after successful completion. Neither
full corrected response has been validated or completed at the time of this
report. Read each run's `progress.json` for current status. Completion alone will
not establish physical validity; check deformation, force conservation, energies
and convergence, especially because source history and rod-objectivity issues
remain. The original Fortran has no verified full energy ledger.

## Relationship to Bowen

The supplied source defines a roughly 3.46 m beam and prescribed cylindrical
indentation over 0.3 s. Bowen Chapter 3 instead uses a 0.60 m beam and a freely
moving 38.4 kg impactor initially at 10.8 m/s. Fixing this source's bugs does not
turn it into that Chapter 3 model or establish agreement with 359.8 kN and
22.70 mm. The original source remains useful for verifying implementation
mechanics, while exact Chapter 3 identity still requires missing model definitions.
